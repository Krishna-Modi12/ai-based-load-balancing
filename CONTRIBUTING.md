# Contributing

1. Read the SRS, architecture, API contract and security notes before changing behaviour.
2. Create a focused `feat/` or `fix/` branch.
3. Add or update tests and documentation with the code change.
4. Run backend tests/lint and frontend typecheck/build/tests that apply to the change.
5. Do not commit `.env`, credentials, private traffic captures, or large generated model artifacts.
6. Open a pull request using the template. Describe design decisions, migration impact, tests run, and screenshots for UI changes.
7. Benchmark claims must link to raw run configuration and data. Do not edit results manually to make a policy look better.
